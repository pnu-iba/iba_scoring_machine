# 001 — 채점 입력 단위: 예측 파일 vs 코드

결정일: 2026-09-19

## 질문

후배 팀이 사이트에 제출하는 것은 무엇인가?
(a) 예측 결과 CSV(`id,price`)만 제출 — Kaggle 방식,
(b) 노트북/스크립트를 제출하고 서버가 실행해서 예측을 생성,
(c) 둘 다.

## 지금 정해야 하는 이유

이 답이 사이트의 성격을 통째로 결정한다. (a)는 파일 검증 + 지표 계산만 있으면 되어 작고 안전하다(정답은 002에서 확보·분리 완료). (b)는 코드 실행 샌드박스·의존성·시간 제한이 필요해 규모가 몇 배 커진다. 004(제출 제한)·005(호스팅)·006(스택)이 모두 이 결정에 걸려 있다.

## 근거 자료

- 기존 자료의 관행: 회귀 베이스라인 노트북은 `sample_submission.csv` 형식(`id,price`)으로 `submit.csv`를 만들어 끝난다 → 이미 (a) 형식이 관례.
- 002 결론: test의 `id`가 고유하지 않아 **행 순서 기준 채점**이 확정됨 → (a)를 택하면 "행 수 39,085 + 순서 보존" 검증이 제출 형식의 핵심 조건이 된다. id를 고유하게 재부여할지는 이 결정에서 함께 다룬다.
- 3조 노트북은 코랩 경로에 의존하고 pip 설치·시각화가 섞여 있어 (b)로 자동 실행하기엔 정리 비용이 큼.

## 결론

(2026-09-19, 사용자 결정) **(a) 예측 결과 CSV만 제출한다.** 코드 실행은 하지 않는다.

- 형식: `sample_submission.csv`와 동일한 `id,price` 두 열. test.csv의 개체 순서대로 각 행에 팀 모델이 예측한 price를 담는다.
- 채점은 `answer.csv`를 기준으로 하며, 002 결론대로 행 순서(위치) 기준이다.
- 이 결정에서 파생되는 검증 규칙(스펙 단계에서 확정): 헤더가 정확히 `id,price`, 행 수 39,085, `id` 열이 test.csv의 id 순서와 완전히 일치(순서 기준 검사), `price`는 결측 없는 숫자. 음수 값 처리는 003에서.
- test.csv의 id를 고유하게 재부여하는 것은 하지 않는다(sample_submission 형식을 그대로 유지하기로 했으므로). 대신 제출 안내에 "행 순서를 바꾸지 말 것"을 명시한다.

## 이후 영향

- 006: 코드 실행 샌드박스가 불필요해져 후보가 "파일 업로드 + pandas 지표 계산" 수준의 소형 백엔드(또는 서버리스)로 좁아진다. 이제 006은 004·005에만 의존한다.
- 미정 항목의 "id 재부여" 질문은 소멸(재부여하지 않기로 함).
- 검증 실패 시 사용자에게 돌려줄 메시지 목록은 스펙 단계에서 정한다.

- 2026-10-02에 test.csv, sample_submission.csv, 정답의 id를 0부터 시작하는 행 번호로 다시 매겼다. 원본 id로 merge하는 채점 템플릿이 서로 다른 차량을 짝지어 점수를 부풀렸기 때문이다. 제출 형식인 `id,price`, 39,085행, test.csv와 같은 순서는 그대로다.
