# 결정 기록

채점 사이트를 만들기 전인 2026년 9월에 무엇을 제출받고, 무엇으로 채점하고, 누가 어떻게 운영할지를 정한 기록이다. 각 문서는 결정할 당시의 질문, 근거, 결론을 그대로 두고, 구현하면서 달라진 내용은 문서 끝의 "구현에서 달라진 점"에 적었다. 현재 동작은 저장소 README와 docs/spec.md를 따른다.

## 결정 목록

| 번호 | 주제 | 결론 |
|---|---|---|
| 001 | 채점 입력 단위 | 코드가 아니라 `sample_submission.csv`와 같은 `id,price` 예측 CSV만 받는다 |
| 002 | 정답 데이터 확보와 보관 | answer.csv를 공식 정답으로 쓰고 행 순서 기준으로 채점한다. 정답은 공개 저장소와 배포 데이터에서 분리한다 |
| 003 | 평가 지표 | RMSE로 순위를 매기고 R²를 함께 보여 준다 |
| 004 | 참가자와 제출 제한 | 팀 단위로 제출하고 팀당 하루 3회로 제한한다 |
| 005 | 운영 주체와 호스팅 | 동아리 홈페이지와 별도인 사이트를 비용 없이 운영하고, 계정은 동아리 공용 계정으로 둔다 |
| 006 | 기술 스택 | Vercel Hobby, Python FastAPI 함수, Neon Postgres Free, 정적 프론트엔드를 쓴다 |
| 007 | 팀 식별 방식 | 사이트 자체 계정으로 가입하고, 가입할 때 적은 팀으로 제출을 묶는다 |

007은 004의 제출 제한을 강제할 방법을 정하고, 006은 004, 005, 007의 조건을 모두 만족하는 플랫폼을 고른다.

## 결정 뒤에 스펙에서 정한 것

- "하루"는 한국 시간 자정에 초기화한다.
- 리더보드에는 팀별 최고 기록을 올린다.
- 음수 예측은 0으로 바꿔 채점한다.
- 2026-10-02에 대회 중에는 test의 30%로 계산한 public 점수만 보여 주고, 마감 뒤 전체 데이터로 최종 순위를 매기기로 했다.
- 미니게임은 채점과 상관없는 기능으로 두되, 게임 점수와 사람별 순위는 서버에 저장한다.
- 운영자는 관리자 페이지에서 일정, 제출, 사용자, 기수 초기화를 관리한다.

## 범위 밖

- German Credit 분류 과제 채점은 2026-09-19에 하지 않기로 했다.
- 참가자가 모델을 학습할 환경을 제공하는 일과 데이터셋 설계를 바꾸는 일은 채점 사이트의 범위가 아니다.

## 원자료

결정할 때 참고한 데이터와 노트북은 `scoring_machine/regression/` 폴더에 있었다. 이 폴더는 저장소에 남아 있지 않으며, 참가자에게 주는 데이터와 baseline 노트북은 `public/data/`에 있다.
