# 동아리 회귀 프로젝트 자동 채점 사이트 — 구현 스펙

작성일: 2026-09-19
근거: [결정 지도](../wayfinder/scoring-site/MAP.md), [기술 스택 조사](../research/scoring-site-tech-stack.md)

## Problem Statement

데이터분석 동아리는 매 기수 후배 팀에게 중고차 가격 예측(회귀) 프로젝트를 내주고, 팀이 만든 모델의 예측 결과를 정답과 비교해 점수를 매긴다. 지금은 운영진이 제출 파일을 받아 손으로 채점하기 때문에 점수가 늦게 나오고, 팀은 모델을 고친 뒤 바로 결과를 볼 수 없으며, 운영진 두 사람이 졸업하면 채점 방법 자체가 사라질 위험이 있다. 또한 제공 자료에는 정답 파일이 섞여 있어(정답 `answer.csv`가 데이터 폴더 안에 있음) 그대로 배포하면 채점이 무의미해진다.

## Solution

팀이 예측 결과 CSV를 업로드하면 즉시 RMSE와 R²를 계산해 돌려주고, 리더보드에 팀별 순위를 보여주는 별도 웹사이트를 만든다. 사이트는 홈 화면, 채점 페이지, 리더보드, 미니게임 네 페이지로 구성된다. 정답은 서버 측 데이터베이스에만 두고, 팀당 하루 3회 제출 제한으로 리더보드 과적합을 억제한다. 제출은 아이디·비밀번호로 로그인한 계정의 팀으로 기록하며, 무료 티어(Vercel Hobby + Neon Free)만으로 운영해 비용 0원을 유지하고 후배 운영진이 이어받을 수 있게 한다.

## User Stories / Acceptance Criteria

### 채점 페이지

1. 후배 팀원으로서, 아이디·비밀번호·닉네임·팀 번호를 적어 가입하고 로그인하고 싶다. 같은 팀 번호를 적은 팀원끼리 한 팀이 된다.
2. 후배 팀원으로서, 로그인한 상태에서 `id,price` 형식의 CSV를 업로드하면 몇 초 안에 RMSE와 R²를 화면에서 보고 싶다. 그래야 모델을 고친 뒤 바로 효과를 확인할 수 있다.
3. 후배 팀원으로서, 제출 파일이 형식에 맞지 않으면 무엇이 잘못됐는지(헤더 불일치, 행 수 불일치, id 순서 불일치, 숫자가 아닌 값, 빈 값) 구체적인 메시지로 알고 싶다. 그래야 채점 없이 실패한 이유를 스스로 고칠 수 있다.
4. 후배 팀원으로서, 오늘 우리 팀이 몇 회 제출했고 몇 회 남았는지 제출 전에 보고 싶다.
5. 후배 팀원으로서, 하루 3회를 다 쓴 상태로 제출하면 채점되지 않고 "오늘 제출 횟수를 모두 사용했다"는 안내와 초기화 시각을 보고 싶다.
6. 후배 팀원으로서, 제출 형식 안내(헤더, 행 수 39,085, test.csv와 같은 순서, 행 순서를 바꾸지 말 것)와 `sample_submission.csv` 다운로드 링크를 채점 페이지에서 보고 싶다.

### 리더보드

7. 동아리원으로서, 팀별로 닉네임·팀 번호·RMSE·R²가 RMSE 오름차순으로 정렬된 리더보드를 로그인 없이 보고 싶다. 대회 중에는 public 구간 점수로, 마감 뒤에는 전체 데이터 점수로 정렬된다.
8. 동아리원으로서, 리더보드의 한 팀 행에는 그 팀의 **public 최고 기록(public RMSE 최소)** 한 건만 표시되고, 그 기록을 낸 닉네임과 제출 시각이 함께 보이길 원한다. 최종 순위에도 이 제출이 쓰인다.
9. 동아리원으로서, RMSE가 같은 팀은 R²가 높은 쪽, 그것도 같으면 먼저 제출한 쪽이 위에 오길 원한다.

### 홈 화면·미니게임

10. 처음 방문한 후배로서, 홈 화면에서 프로젝트 소개, 리더보드 상위 팀, 데이터 설명(train/test/brand_model/sample_submission), 채점 방식(RMSE 주 지표, R² 보조), 제출 규칙(하루 3회, 행 순서 유지)을 한 번에 읽고 채점 페이지·리더보드로 이동하고 싶다.
11. 동아리원으로서, 채점과 무관한 가벼운 미니게임을 하고, 게임마다 팀별 최고 점수 순위를 보고 싶다. 로그인한 상태로 게임을 마치면 점수가 우리 팀 기록으로 올라간다.

### 운영

12. 운영자로서, 잘못된 제출(남의 팀 번호로 가입한 계정의 제출, 장난 제출)을 관리자 페이지에서 삭제해 리더보드와 해당 팀의 오늘 제출 횟수를 바로잡고, 실수로 지운 제출은 복구하고 싶다.
13. 운영자로서, 정답 파일을 git 저장소에 넣지 않고도 배포·채점이 되길 원한다. 저장소가 공개되어도 정답이 새지 않아야 한다.
14. 운영자로서, 대회 기간과 하루 제출 횟수, 공지를 배포 없이 관리자 페이지에서 바꾸고 싶다.
15. 운영자로서, 기수가 끝나면 결과를 내려받아 보관하고, 제출 기록과 지난 기수 계정을 관리자 페이지에서 비우고 싶다. 데이터셋과 정답은 기수가 바뀌어도 그대로 쓴다.
16. 운영자로서, 팀 번호를 잘못 적고 가입한 학생을 다른 팀으로 옮기고, 비밀번호를 잊은 학생에게 임시 비밀번호를 발급하고 싶다.

### 제약·엣지 케이스

17. 제출 CSV의 `id` 열은 test.csv와 **행 순서까지** 같아야 하며, 채점은 위치 기준으로 비교한다. test.csv·answer.csv·sample_submission.csv의 id는 0부터 39,084까지의 행 번호다. 원본 데이터의 id는 39,085행 중 고유값이 31,573개뿐이라 서로 다른 차량이 같은 id를 가졌고, id로 merge하면 다른 차량끼리 짝지어져 점수가 부풀었다(3조 제출 기준 RMSE 1,985 → 7,882). 그래서 배포 전에 세 파일의 id를 행 번호로 다시 매겼다.
18. `price`에 음수가 있으면 거부하지 않고 0으로 클리핑한 뒤 채점하며, 결과 화면에 "음수 n건을 0으로 처리했다"고 알린다. (기존 노트북 관행과 일치.)
19. `price`가 비어 있거나 숫자가 아닌 행이 하나라도 있으면 채점하지 않고 거부한다.
20. 팀은 숫자로 된 팀 번호로만 받는다. 앞뒤 공백을 지우고 전각 숫자를 반각으로 바꾼 뒤 앞자리 0을 떼어 같은 팀으로 본다(3과 03은 같은 팀). 숫자가 아닌 글자가 있으면 가입을 거부한다.
21. "하루"는 한국 시간(KST) 자정에 초기화된다.
22. 업로드 파일 크기는 2 MB를 넘으면 거부한다(정상 제출은 약 0.5 MB, 플랫폼 본문 한도 4.5 MB 이내 여유).

## Implementation Decisions

### 전체 구성

- 호스팅은 Vercel Hobby, 백엔드는 Python FastAPI 단일 앱을 Vercel Functions로 실행, 데이터베이스는 Neon Postgres Free. 프론트는 프레임워크 없는 정적 HTML/CSS/JS 네 페이지와 로그인·회원가입 페이지. (결정 006)
- 저장소는 동아리 GitHub 조직의 공개 저장소. Vercel Hobby는 조직 비공개 저장소에서 배포할 수 없으므로 공개가 전제이며, 따라서 정답 파일은 어떤 형태로도 저장소에 커밋하지 않는다. `scoring_machine/regression/answer.csv`는 이 저장소에서 제거하거나 `.gitignore`로 막는다. (결정 002, 005, 006)
- 비밀값은 Vercel 환경변수 두 개: 데이터베이스 연결 문자열, 세션 서명 키. 관리자는 키가 아니라 계정 권한(`users.is_admin`)으로 구분한다.
- 채점 연산은 Python 표준 라이브러리(`csv`, `math`)만 사용한다. pandas/numpy는 콜드 스타트만 늘리고 이 규모(39,085행)에서 이점이 없다. 조사 시 벤치마크: 두 파일 파싱 + 계산이 수십 ms 수준.

### 데이터 모델 (Neon)

- `answers`: `row_no`(0부터 시작하는 위치, 기본키), `id`(test.csv의 id, 참고용), `price`(정답), `in_public`(public 채점 구간 여부). 39,085행. 처음 배포할 때 운영자가 스크립트로 1회 적재하고 기수가 바뀌어도 그대로 쓰며, 이때 전체의 30%를 중복 없이 무작위로 골라 public 구간으로 표시한다.
- `users`: `id`(자동), `username`(로그인 아이디, 소문자, 고유), `password_hash`(PBKDF2-SHA256), `nickname`, `team_key`(정규화된 팀 번호), `team_display`(리더보드 표기, team_key와 같음), `created_at`, `is_admin`(관리자 여부).
- `submissions`: `id`(자동), `team_key`(정규화된 팀 번호), `team_display`(제출자 팀의 표기), `nickname`, `rmse`·`r2`(전체 데이터 점수), `public_rmse`·`public_r2`(public 구간 점수), `negative_clipped`(0으로 처리한 건수), `submitted_at`(UTC 저장, 표시·일 계산은 KST 변환), `deleted_at`(관리자 삭제 시 기록; 삭제된 행은 리더보드·횟수 계산에서 제외).
- `game_scores`: `id`(자동), `game`, `team_key`, `team_display`, `nickname`, `score`, `played_at`. 미니게임을 마칠 때마다 한 행.
- `contest_settings`: 한 행. `start_date`(첫날, KST), `end_date`(마지막 날, KST), `daily_limit`(팀당 하루 제출 횟수). 관리자 페이지에서 바꾸며, 행이 없으면 스키마 스크립트가 첫 기수 일정으로 만든다.
- `notices`: `id`(자동), `title`, `notice_date`. 리더보드의 공지사항 카드에 날짜 역순으로 보인다.
- 제출 파일 원본은 저장하지 않는다. 점수와 메타데이터만 남긴다. 그래서 대회 중에 정답 오류가 발견되면 기존 제출을 다시 채점할 수 없다.

### 채점 규칙 (결정 001, 002, 003)

- 검증 순서: 파일 크기 → UTF-8 텍스트 파싱 → 헤더가 정확히 `id,price` → 데이터 행 수 39,085 → 각 행의 id가 `answers.row_no` 순서의 id와 일치 → `price`가 모두 유한한 숫자. 첫 실패 지점에서 해당 사유와 (가능하면) 문제 행 번호를 반환한다.
- 음수 price는 0으로 클리핑하고 건수를 기록한다.
- RMSE = sqrt(mean((y − ŷ)²)), R² = 1 − Σ(y − ŷ)² / Σ(y − ȳ)². 소수점은 저장 시 전체 정밀도, 표시 시 RMSE 소수 2자리·R² 소수 4자리.
- 제출마다 public 구간(전체의 30%)과 전체 데이터 두 가지로 점수를 계산해 저장한다. 대회 중 응답과 리더보드에는 public 점수만 내보낸다. 제출할 때마다 점수가 보이면 테스트셋이 사실상 validation set이 되므로, 최종 순위는 학생이 점수로 확인하지 못한 행이 들어간 전체 데이터로 매긴다.
- 대회 상태는 설정에서 정한다. 시작일 0시(KST) 전은 준비로 제출을 403 `contest_not_started`로 거부하고, 마지막 날 다음 날 0시부터는 결과 공개로 제출을 403 `contest_closed`로 거부하며 리더보드를 최종 순위로 바꾼다. 최종 순위는 팀마다 public 점수가 가장 좋았던 제출 1건의 전체 데이터 점수로 정한다.
- 정답은 함수 인스턴스 안에서 첫 요청 시 한 번 읽어 메모리에 캐시한다(인스턴스 재사용 시 DB 재조회 없음).

### 제출 제한 (결정 004, 007)

- 팀 식별은 로그인한 계정의 `team_key`로 한다. 세션은 `사용자id.만료시각.서명` 형식의 HttpOnly 쿠키(30일)이고, 서명은 세션 서명 키로 만든 HMAC-SHA256이다.
- 제출 처리 순서: 정규화 → 오늘(KST) `deleted_at IS NULL`인 제출 건수 조회 → 설정의 하루 횟수 이상이면 429와 초기화 시각 반환 → 파일 검증·채점 → 기록 삽입. 동시 제출 경쟁으로 4회가 기록될 가능성은 받아들인다(신뢰 집단, 실수 방지 수준이 목표).
- 남은 횟수 조회는 채점 페이지에서 로그인한 계정의 팀 기준으로 제공한다.

### API 계약

- `POST /api/signup` — JSON `{ username, password, nickname, team }`. 성공 200: `{ username, nickname, team }` + 세션 쿠키. 형식 오류 400, 아이디 중복 409. 아이디는 영문 소문자·숫자·밑줄 4~20자, 비밀번호 8~72자.
- `POST /api/login` — JSON `{ username, password }`. 성공 200 + 세션 쿠키, 실패 401. `POST /api/logout` — 쿠키 삭제.
- `GET /api/me` — 로그인한 사용자 `{ username, nickname, team, is_admin }`, 로그인하지 않았으면 `null`.
- `GET /api/contest` — `{ start, end, status, final_at, daily_limit, notices }`. `status`는 `ready`·`open`·`final`.
- `POST /api/submit` (로그인 필요) — multipart: `file`. 로그인하지 않았으면 401. 성공 200: `{ rmse, r2, negative_clipped, remaining_today, rank }`(점수와 순위는 public 기준). 검증 실패 400: `{ error_code, message, row? }`. 한도 초과 429: `{ message, resets_at }`. 시작 전 403 `contest_not_started`, 마감 뒤 403 `contest_closed`, 관리자 계정 403 `admin_cannot_submit`.
- `POST /api/games/{game}/score` (로그인 필요) — JSON `{ score }`. `game`은 `apple`(상한 170), `tetris`, `blocks`. 성공 200: `{ rank, team_best }`. 없는 게임 404, 범위 밖 점수 400.
- `GET /api/games/{game}/leaderboard` — 팀별 최고 점수: `[{ rank, team, nickname, score, played_at }]`. 점수 내림차순, 동점이면 먼저 기록한 쪽.
- `GET /api/leaderboard` — `{ final, final_at, rows }`. `rows`는 팀별 public 최고 기록 `[{ rank, team, nickname, rmse, r2, submitted_at }]`. 대회 중에는 public 점수로, `final`이 참이면 전체 데이터 점수로 정렬하고 각 행에 `public_rmse`, `public_r2`, `public_rank`를 더한다. RMSE 오름차순, 동점 시 R² 내림차순, 그다음 `submitted_at` 오름차순.
- `GET /api/quota` (로그인 필요) — 우리 팀의 `{ used_today, remaining_today, resets_at, limit }`.
- `/api/admin/*` — 관리자 계정으로 로그인해야 한다. 비로그인 401, 일반 사용자 403. 권한은 요청마다 DB에서 읽은 계정으로 확인한다.
  - `GET /overview` — 대회 상태, 시작·마감 시각, 정답 행 수, 제출 수, 가입자 수.
  - `PUT /contest` — `{ start, end, daily_limit }`. 시작일이 마지막 날보다 늦거나 횟수가 1-100 밖이면 400.
  - `POST /notices`, `PUT /notices/{id}`, `DELETE /notices/{id}` — 공지 관리.
  - `POST /score-check` — multipart `file`. 기록과 횟수에 남기지 않고 public·전체 점수를 돌려준다.
  - `GET /submissions?team=&include_deleted=` — 제출 목록, 최신순. `DELETE /submissions/{id}`는 소프트 삭제, `POST /submissions/{id}/restore`는 복구(그날 한도는 다시 확인하지 않음). 대상이 없으면 404.
  - `GET /users?team=` — 사용자 목록(비밀번호 해시 제외). `PATCH /users/{id}` — `{ team?, is_admin? }`. 팀을 옮겨도 이미 낸 제출은 원래 팀에 남는다. 자기 자신의 관리자 권한은 해제할 수 없다. `POST /users/{id}/reset-password` — 임시 비밀번호를 만들어 한 번 돌려준다.
  - `GET /export` — 최종 순위·전체 제출·사용자·미니게임 점수 CSV 네 개를 묶은 zip.
  - `POST /reset` — `{ confirm, delete_games, delete_users }`. `confirm`이 `<마지막 날> 대회 초기화`와 다르면 400. 제출 기록은 항상, 미니게임 점수와 관리자가 아닌 계정은 고른 경우에 한 트랜잭션으로 지운다. 정답, 대회 설정, 공지는 남긴다.

### 페이지

- 홈: 소개·리더보드 상위 5팀(로그인했고 우리 팀이 5위 밖이면 우리 팀 행 추가)·데이터 설명·채점 방식·제출 규칙·데이터 다운로드 링크(train/test/brand_model/sample_submission은 정적 파일로 제공; answer는 절대 포함하지 않음).
- 채점: 로그인하지 않았으면 로그인·회원가입 안내. 로그인했으면 파일 선택, 남은 횟수 표시, 제출 결과(점수·현재 순위·음수 처리 안내) 또는 오류 메시지 표시.
- 리더보드: 표 하나. 페이지 로드 시 조회, 새로고침 버튼. 캐시 없이 매번 조회(요청량이 작다).
- 미니게임: 게임 목록 페이지와 사과게임·테트리스·블록깨기 페이지. 게임은 브라우저에서만 돌고, 조작은 키보드·마우스만 지원한다. 개인 최고 기록은 브라우저(localStorage)에 저장한다. 게임 페이지마다 팀 순위 표가 있고, 로그인한 상태로 게임을 마치면 점수를 서버에 기록한다. 점수는 브라우저가 계산해 보내므로 게임별 상한을 넘는 값만 거절하고, 그 이상의 조작 방지는 하지 않는다.
- 로그인·회원가입: 가입 후 원래 보던 페이지로 돌아간다.
- 관리자: 관리자 계정에만 사이드바 메뉴가 보인다. 현황, 대회 설정과 공지, 제출, 사용자, 채점 확인과 초기화 다섯 탭. 기수 초기화는 결과 zip을 내려받고 확인 문구를 입력해야 실행된다.
- 공통 셸: 왼쪽 사이드바 내비게이션, 상단바의 로그인 상태(로그인·회원가입 버튼 또는 닉네임·팀과 로그아웃).

### 기수 교체 절차 (결정 005)

- 관리자 페이지에서 처리한다: (1) 결과 zip 내려받기, (2) 기수 초기화(제출 기록, 기본으로 관리자가 아닌 계정과 미니게임 점수), (3) 대회 설정에서 다음 기수 날짜와 공지 정리. 팀 번호를 기수마다 다시 쓰므로 지난 기수 계정과 점수를 남기면 새 팀에 섞인다.
- 데이터셋과 정답은 바꾸지 않으므로 정적 데이터 파일 교체와 정답 재적재는 없다.
- 첫 관리자는 가입한 계정에 `scripts/grant_admin.py`로 권한을 주고, 그 뒤로는 관리자 페이지에서 지정한다.
- 플랫폼 계정(Vercel, Neon, GitHub 조직)은 동아리 공용 이메일로 만들고, 운영 문서에 계정 인수인계 항목을 둔다.

## Validation Decisions

- 좋은 테스트는 채점 API의 **외부 동작**만 본다: 특정 CSV를 넣으면 특정 상태 코드와 점수·오류 코드가 나오는지. 내부 파싱 함수나 DB 스키마는 직접 검사하지 않는다.
- 채점 정확성 기준값: `sample_submission.csv`를 그대로 제출하면 전체 데이터 RMSE ≈ 13,189.79, R² ≈ −0.79가 나와야 한다(조사 중 실측). `answer.csv` 자체를 제출하면 RMSE 0, R² 1이어야 한다. 이 두 파일이 회귀 테스트의 고정 입력이다.
- 검증 실패 케이스별 테스트 입력을 만든다: 헤더 오타, 행 하나 누락, 두 행 순서 바꿈, price 빈 값, price 문자열, 음수 price(클리핑 후 성공 + 건수 확인), 2 MB 초과 파일.
- 계정 테스트: 가입·로그인·로그아웃, 아이디 중복과 대소문자, 형식 오류, 비밀번호 평문 미저장, 변조·만료된 세션 거부, 로그인 없이 제출·횟수 조회 시 401.
- 제출 제한 테스트: 같은 팀 번호(표기 변형 포함 — 공백·앞자리 0·전각 숫자)로 가입한 계정들로 3회 성공 후 4회째 429; 관리자 삭제 후 다시 제출 가능, 복구하면 다시 막힘; KST 자정 경계는 시각을 주입할 수 있게 해 테스트.
- 리더보드 테스트: 한 팀이 여러 번 제출해도 한 행, 최고 RMSE 기준; 동점 정렬 규칙; 삭제된 제출은 제외.
- 테스트는 FastAPI의 테스트 클라이언트로 API 레벨에서 작성하고, DB는 테스트용 Neon 브랜치 또는 로컬 Postgres를 쓴다. 이 저장소에는 아직 선례가 되는 테스트가 없다.
- 프론트는 자동 테스트 없이 수동 확인: 네 페이지 이동, 채점 성공·실패·한도 초과 세 가지 화면, 리더보드 정렬.
- 배포 후 확인: 공개 저장소에 정답 파일이 없는지, 정적 경로로 정답에 접근되지 않는지, Vercel 함수 로그에서 첫 요청(콜드 스타트) 소요 시간 실측.

## Out of Scope

- 분류 과제(German Credit) 채점 — 폐기 결정.
- 팀 코드 발급, 가입 코드, 외부 로그인(Google 등) — 자체 계정으로 확정.
- 학생 스스로 하는 팀 번호 변경과 비밀번호 재설정 — 운영자가 관리자 페이지에서 처리한다.
- 모바일·태블릿 화면과 터치 입력 — PC 브라우저에서만 쓰는 것을 전제로 한다.
- 코드/노트북 제출과 서버 실행 — 예측 CSV만 받는다.
- 정답·데이터셋 교체 UI — 기수가 바뀌어도 같은 데이터셋을 쓴다.
- 관리자 작업 기록(누가 무엇을 했는지) — 운영진이 두세 명이라 두지 않는다.
- 점수 외 상세 피드백(오차 분포, 구간별 오차) — 첫 버전에서는 RMSE·R²·음수 처리 건수만.
- 후배용 모델 학습 환경 제공, 기존 3조 노트북 개선.
- 동아리 홈페이지(`pnu-iba-homepage/`)와의 통합.
